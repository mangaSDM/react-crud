Báo cáo bài tập React CRUD — Quản lý người dùng

Ứng dụng web xây dựng bằng React 18 (nhúng qua CDN cùng ReactDOM và Babel Standalone trong một file HTML), hỗ trợ đầy đủ các chức năng Tìm kiếm, Thêm, Sửa, Xóa (CRUD). Dữ liệu ban đầu được tải từ API mẫu https://jsonplaceholder.typicode.com/users; các thao tác thêm/sửa/xóa cập nhật trực tiếp trên state của React tại trình duyệt.

Trang ứng dụng: Mở ứng dụng Quản lý người dùng (index.html)

1. Sơ đồ Component (Component Tree)

App là component gốc quản lý 3 component con trực tiếp: SearchForm, AddUser và ResultTable. Để tránh lặp lại mã JSX cho 8 trường nhập liệu (gồm cả 3 trường lồng trong address), phần các ô input được tách thành component dùng chung UserFormFields và hàm tiện ích updateUserField.

2. Luồng dữ liệu và State Lifting

Ứng dụng tuân thủ luồng dữ liệu một chiều theo hai nhánh chính:

  • Tìm kiếm: Người dùng nhập vào SearchForm → gọi onChangeValue (chính là setKw) → App cập nhật kw → truyền kw xuống ResultTable để lọc bằng Array.filter() theo cả name và username.
  • Thêm người dùng: Người dùng nhập form ở AddUser và bấm Thêm → gọi onAddUser(user) (chính là setNewUser) → App truyền newUser xuống ResultTable → useEffect([newUser]) thêm người dùng vào mảng users với id tự tăng rồi gọi onAdd() để đặt newUser về lại null.

Vì sao cần State Lifting ở App?

  • Trong React, dữ liệu chỉ truyền từ cha xuống con qua props; các component anh em (SearchForm, AddUser, ResultTable) không thể truyền trực tiếp cho nhau.
  • Nâng kw và newUser lên cha chung gần nhất (App) giúp đồng bộ trạng thái giữa nơi nhập liệu và nơi hiển thị bảng mà vẫn giữ một nguồn dữ liệu duy nhất.
  • Các state nội bộ như users, editing (chỉ ResultTable dùng) hoặc adding, user (chỉ AddUser dùng) được giữ cục bộ trong chính component đó.

4. Các lỗi gặp phải trong quá trình thực hiện và cách khắc phục

Lỗi 1 (Bước 1): Trang trắng / lỗi cú pháp do copy thẻ <script> từ PDF

Hiện tượng: Mở file index.html không hiển thị chữ "Quản lý người dùng", Console báo lỗi tải thư viện và lỗi cú pháp ở thẻ <div> trong JSX.

Nguyên nhân: Đường dẫn CDN của react-dom bị ngắt xuống dòng và mất dấu gạch nối (react dom.development.js); đồng thời thuộc tính type của thẻ <script> bị dính dấu ngoặc kép cong (“text/babel”) khiến Babel không nhận diện để biên dịch JSX.

Cách sửa: Nối liền URL chuẩn react-dom.development.js và dùng dấu ngoặc kép thẳng type="text/babel".

Sau khi sửa, React 18 và Babel hoạt động bình thường, render thành công component gốc App.

Lỗi 2 (Bước 4): Lỗi runtime khi hiển thị danh sách ResultTable và khai báo AddUser

Hiện tượng: Ứng dụng crash khi render với các lỗi ReferenceError: filteredUsers is not defined, lỗi React 18 vì AddUser trả về undefined, và cấu trúc DOM không hợp lệ do thiếu <table>.

Nguyên nhân:

  • Gõ nhầm tên biến filtereUsers (thiếu chữ d) nhưng bên dưới lại gọi filteredUsers.map(...).
  • ResultTable trả về trực tiếp <tbody> mà không có <table> và <thead> bao ngoài.
  • Component tạm function AddUser({onAddUser}) {} không có lệnh return, dẫn đến trả về undefined.

Cách sửa: Sửa đúng tên biến filteredUsers (đồng thời lọc theo cả name và username), bọc <table> + <thead> bên ngoài <tbody>, và trả về null (trước khi hoàn thiện Bước 5).

Bảng hiển thị đầy đủ 10 người dùng từ API và lọc theo từ khóa ngay lập tức.

Lỗi 3 (Bước 5 & 7): Xử lý trùng key sau khi xóa và tránh lỗi gọi hàm ngay lúc render

Vấn đề tiềm ẩn từ mã minh họa: (1) Đặt id: prev.length + 1 sẽ tạo ra ID trùng (ví dụ xóa ID 1 còn 9 người, thêm mới ra ID 10 trùng với người cuối), gây cảnh báo two children with the same key. (2) Viết onClick={setAdding(false)} sẽ gọi hàm ngay lúc render thay vì lúc bấm nút.

Cách xử lý trong bài: Tính ID mới bằng giá trị lớn nhất hiện có cộng 1, và luôn truyền hàm callback cho onClick.

// Sinh ID an toàn không bị trùng sau khi xóa
const nextId = prev.length > 0 ? Math.max(...prev.map((u) => u.id)) + 1 : 1;
return [...prev, { ...newUser, id: nextId }];

// Truyền hàm callback cho sự kiện click
<button onClick={handleCancel}>Hủy</button>
Thêm mới sau khi xóa luôn sinh ID kế tiếp hợp lệ (ví dụ ID 11), không có warning trong Console và modal đóng/mở đúng thao tác.
